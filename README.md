# Shree Collection — श्री Collection

The shopping site for **Shree Collection**, a ladies' garments store in Banswara, Rajasthan
(suits and sarees). The home page is a scroll-scrubbed film, *Vrindavan Noir*: one golden
thread (*Ek Dhaaga*) runs from the badge, through silk, sarees and suits, to a map of
Banswara, and ties a knot back into the badge. The shop, product, bag and WhatsApp checkout
work fully without the film.

```bash
npm install
npm run dev        # http://localhost:3000
npm run build && npm start
```

Node 20.9+ is required. `npm run lint` and `npm run typecheck` should both be clean.

## Before launch: what the owner still needs to provide

Every brand fact lives in [`src/brand.config.ts`](src/brand.config.ts). Unknown values stay
empty and the site never shows a placeholder for them: the row or button is hidden (no address
line, no hours, no Call button). Fill a value in once and it appears in the header, footer, Visit
page, product pages, JSON-LD and checkout. `brandTodos` in that file lists what is still missing.

| Missing | Where it goes |
| --- | --- |
| Corrected logo master (the supplied raster reads **LADIES GARAIENTS**) | `public/brand/logo.png`, then `logo.hasArtwork: true` |
| Street address, PIN code | `location.streetAddress`, `location.postalCode` |
| Phone and WhatsApp number | `contact.phone`, `contact.whatsapp` (digits with country code) |
| Opening hours | `hours` |
| Owner story | `ownerStory` |
| Shipping, returns and privacy policies | `policies.*` |
| Production domain (if not the Vercel URL) | `NEXT_PUBLIC_SITE_URL`; otherwise Vercel's production URL, else `https://shreecollections.vercel.app` |
| Real product photos | `public/products/<slug>/photo-*.webp` + `photos` in the data (see below) |
| Optional sound | `public/audio/` (see its README) |

Until the WhatsApp number is set (international format, digits only, no "+"), every WhatsApp
button becomes "Order on Instagram" / "Message on Instagram" (`https://ig.me/m/shreecollectionsbsw`)
and copies the order text so it can be pasted into the chat (`whatsappLink()` in
`src/lib/whatsapp.ts`). The **Pay online** button is reserved for Razorpay and disabled.

Until `logo.png` exists, the site shows a typographic badge (gold ring, mor pankh eye,
श्री COLLECTION). It never redraws the Krishna artwork, and the logo is only ever floated,
tilted and lit — never distorted. The tagline is always live text:
*Ladies Garments · Suits · Sarees*.

## Adding and editing products

Products live in [`data/products.json`](data/products.json). The seed of 24 (12 sarees,
12 suits) is generated by `scripts/seed-products.mjs`; once real stock exists, edit the JSON
directly. Each product:

```ts
{
  id, slug, name, nameHi,
  category: 'saree' | 'suit', subcategory,         // subcategory is free text (Anarkali, Banarasi…)
  fabric: 'Banarasi' | 'Chanderi' | 'Georgette' | 'Cotton' | 'Bandhani' | 'Leheriya' | 'Silk' | 'Other',
  colorFamily, colorHex,                           // colorFamily must be a key of COLOR_FAMILIES
  occasion: ['festive' | 'wedding' | 'party' | 'daily' | 'office'],
  price, mrp?,                                      // INR
  images: ['/products/<slug>/1.webp', …],
  fabricTexture?: '/products/<slug>/fabric.webp',  // tileable, for "Feel the fabric"
  sizes?: ['XS', …], stitched, inStock,
  badges?: ['new' | 'bestseller' | 'limited'],
  description, care: []
}
```

The JSON is validated with Zod on every build (`src/lib/catalog.server.ts`); a typo fails
the build with a readable message instead of shipping a broken page.

**Photos.** Add real photos (4:5, 1600 × 2000 px) as `public/products/<slug>/photo-1.webp` …
and list them in the product's `photos` array; see [`docs/photo-guide.md`](docs/photo-guide.md).
Products without `photos` keep the drawn placeholders; `next/image` serves the right size and
format to each device. The placeholders (textile pattern and drape on an ivory wall, 4:5) come
from `npm run assets` — **that command overwrites `1.webp`–`3.webp` and `fabric.webp` in
`public/products/` and the files in `public/lookbook/`** (`npm run assets -- --products-only`
leaves the lookbook alone). It never touches `photo-*.webp`.

**Lookbook.** Curated images in `public/lookbook/look-1.webp` … `look-8.webp`. Instagram is a
link only: no embed, no scraping.

## Swapping the data layer

Components only import from [`src/lib/catalog.ts`](src/lib/catalog.ts)
(`getAllProducts`, `getProduct`, `getByCategory`, `getBestsellers`, …). To move to Shopify
Storefront, Supabase or Sanity, rewrite those functions to fetch and map into the same
`Product` shape (`src/lib/catalog.schema.ts`); nothing else changes. Pages are statically
generated, so fetch at build time (or add revalidation if stock changes often).

## How the film works

* **One clock.** `gsap.ticker` drives Lenis, ScrollTrigger and R3F (`frameloop="never"` +
  `advance()`), so DOM, scroll and WebGL update in the same frame — `src/lib/clock.ts`,
  `src/film/TickerDriver.tsx`.
* **Scroll state without re-renders.** ScrollTrigger writes the module-level `film` object
  (`src/film/state.ts`); shots read it in `useFrame` and damp toward it. No `setState` on
  scroll or per frame.
* **Chapter registry.** `src/film/chapters.ts` — id, labels and scroll length in svh
  (desktop / mobile). The DOM section (`src/film/dom/*`) holds the real text; the shot
  (`src/film/shots/*`) renders behind it. Each chapter has one scrubbed timeline that tweens
  DOM and shot values together.
* **Camera rail.** One `CatmullRomCurve3` through a station per chapter
  (`src/film/rail.ts`); the golden thread is a `TubeGeometry` on a sibling curve, revealed
  ahead of the camera.
* **Loading.** Posters paint first. The three.js chunk loads on the visitor's first
  pointer, scroll, key or touch (or after 4 s), during idle. Canvas textures are drawn once,
  in idle slices (`src/film/canvases.ts`). Shots mount two chapters early, are
  pre-compiled with `compileAsync`, draw only near the camera, and unmount (disposing GPU
  memory) when more than three chapters away.
* **Hindi in 3D.** The giant श्री is extruded from a path shaped by HarfBuzz at build time
  (`scripts/build-shri-glyph.mjs` → `src/film/shri-glyph.json`). Never `TextGeometry`.

## Quality tiers

Chosen in `src/lib/tier.ts` from detect-gpu (benchmarks self-hosted in `public/detect-gpu`,
copied on `predev`/`prebuild`), `deviceMemory`, Save-Data and reduced motion. drei's
`PerformanceMonitor` lowers the pixel ratio, then the tier, if frames drop.

| Tier | Devices | DPR | Gold dust | Silk segments | Post FX |
| --- | --- | --- | --- | --- | --- |
| 3 | desktop GPUs | 1–2 | 20k | 200 | bloom |
| 2 | most phones, laptops | 1–1.5 | 6k | 96 | glow sprites |
| 1 | older Android | 1 | 1.5k | 48 | none |
| 0 | no WebGL, Save-Data, reduced motion | — | — | — | captured posters |

Tune the numbers in `TIER_SETTINGS`. Force a tier with `?tier=0` … `?tier=3`.

**Debug and capture** (development builds, or `NEXT_PUBLIC_FILM_DEBUG=1 npm run build`;
compiled out of normal production builds):

* `?debug` — frame timing, current chapter and every film value, plus tier switches.
* `?capture` — exposes `window.__capture()`, which renders one frame as WebP. The tier-0
  posters in `public/posters/{d,m}-<chapter>.webp` were made this way (desktop at tier 3,
  1440 × 900; mobile at tier 2, 390 × 844). Re-capture after changing a shot.

## Map data

`public/geo/rajasthan.topo.json` holds Rajasthan's outline and districts only — never a
national outline. Source: [geoBoundaries](https://www.geoboundaries.org/) gbOpen IND ADM2
(2021; LGD / Pathways Data), licensed **ODbL 1.0**, simplified with mapshaper (credited under
the map). That dataset shows **33 districts** and predates Rajasthan's 2023–24 district
reorganisation; swap in a newer openly licensed file when one is available (filter to
Rajasthan, `-simplify 6% keep-shapes`, `-dissolve2` for the outline, export TopoJSON with
`districts` and `state` objects).

## Measured so far (and what isn't)

Measured in a headless Chromium **with software WebGL and no GPU**, so frame rates and
blocking time on the home page are pessimistic. Lighthouse mobile:

| Page | Performance | Accessibility | Best practices | SEO | LCP |
| --- | --- | --- | --- | --- | --- |
| `/` | 68 (simulated) / 60 (applied) | 100 | 100 | 100 | 1.9 s applied |
| `/shop` | 88 (applied) | 100 | 100 | 100 | 1.8 s |
| `/product/…` | 94 (applied) | 100 | 100 | 100 | 1.9 s |

CLS is 0–0.001 everywhere. JavaScript before the 3D chunk is **303 KB gzipped**, over the
180 KB budget: react-dom (70 KB), the Next.js runtime (44 KB) and GSAP with its plugins
(60 KB) already total 174 KB before any app code. Fonts are 246 KB (Devanagari faces are
large).

**Still to do on real hardware:** a full forward-and-back scroll on a mid-range Android
(Snapdragon 6-series) and an iPhone in Safari with a performance trace, per the brief's
50–60 fps target. None of the frame-rate numbers above come from a real GPU.

## Choices made where the brief was silent

* Cache Components is off: Next 16 would keep visited routes mounted in a hidden
  `<Activity>`, which would keep the WebGL context and pinned timelines alive behind the shop.
* Pinned chapters use CSS `position: sticky` with scrubbed timelines rather than
  ScrollTrigger pin spacers — native touch momentum is never fought.
* The local HDRI is replaced by drei `Lightformer`s rendered into an environment map at
  runtime: no remote presets, nothing to download.
* Colour variants on product pages link to sibling products of the same style.
* The pincode check is a clearly labelled estimate until the shipping policy exists.
* The 404 page is "Lagta hai kisi ne makhan chura liya" with a tipped-over matki.
